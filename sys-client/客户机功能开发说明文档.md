# SYS-client 客户机功能开发说明

> 模块: `sys-client` | 包: `com.java110.api.SYSclient`

---

## 一、概述

SYS-client 是实现客户机与上位机通信的核心模块，负责：

- 与上位机建立 WebSocket 长连接
- 注册客户机身份与关联数据（小区/商户/微信APPID）
- 维持心跳检测与断线重连
- 处理上位机下发的入站业务请求（INBOUND_REQUEST）
- **拦截出站 HTTP 请求并转发到上位机代理**（ClientHttpRequestInterceptor）

**数据同步规范**: 客户机不主动上报任何数据，所有业务数据由上位机通过 INBOUND_REQUEST 按需拉取。

### 架构图

```
┌─────────────────────────────────────────────┐
│              上位机 (Host Computer)            │
│   WebSocket Server  ←→  HTTP Proxy           │
└──────────────────┬──────────────────────────┘
                   │  WebSocket (wss/ws)
                   │  消息协议: REGISTER /
                   │  HEARTBEAT / INBOUND_REQUEST /
                   │  INBOUND_RESPONSE
                   ▼
┌─────────────────────────────────────────────┐
│          客户机 (SYS-client Module)            │
│                                              │
│  SysWebSocketClient  ←→  InboundProxyHandler │
│  OutboundProxyInterceptor ←→ OutboundProxyBeanPostProcessor │
│  LocalIdUpdater  ←→  SysClientProperties     │
└─────────────────────────────────────────────┘
```

### 2.1 SysWebSocketClient — WebSocket 长连接客户端

**职责**: 与上位机建立并维护 WebSocket 长连接。

**生命周期**:

```
应用启动(ApplicationReadyEvent)
    │
    ▼
connectToHost()
    │
    ▼
onOpen() → sendRegister()
    │               │
    ▼               ▼
onMessage()    REGISTER_ACK
    │               │
    ├── OK ──────── startHeartbeat()
    ├── CONFLICT ── closeQuietly() → LocalIdUpdater.resolveConflicts() → reconnect
    └── INVALID_KEY ── 终止连接，不再重连
```

**重连策略**:

| 场景 | 策略 | 默认值 |
|------|------|--------|
| 从未成功连接过（上位机未上线） | 固定长间隔 | 600 秒（10分钟） |
| 曾成功连接后断线（瞬断） | 指数退避 | 1s → 2s → 4s → ... → 60s（最大） |
| KEY 无效（INVALID_KEY） | 不重连 | 人工介入 |

### 2.2 InboundProxyHandler — 入站代理处理器

**职责**: 处理上位机转发的 INBOUND_REQUEST，透传给原项目 API 管线。

**处理流程**:

```
上位机 INBOUND_REQUEST
    │  { method, path, headers, body }
    ▼
extractServiceCode(path)
    │  /api/user.listUser → user.listUser
    ▼
buildApiHeaders()   ← 注入系统管理员身份
    │  X-Host-Key 验证通过 → levelCd=00
    ▼
apiServiceSMOImpl.service()   ← 调用原项目 API
    │
    ▼
封装 INBOUND_RESPONSE 返回上位机
```

**KEY 特性**:
- 验证 `X-Host-Key` 请求头匹配 `authKey` 后，自动注入系统管理员身份（`levelCd=00`）
- 确保上位机有权访问所有社区数据，无需传递具体用户身份
- 自动补充缺失的 API 管线必需字段（transactionId, reqTime, userId 等）

### 2.3 OutboundProxyInterceptor — 出站代理拦截器（核心）

**职责**: 通过 Spring ClientHttpRequestInterceptor 机制，拦截 `outRestTemplate` 的所有 HTTP 请求，将外部 API 调用转发到上位机代理。

**拦截机制**:
- 通过 `OutboundProxyBeanPostProcessor` 自动向 `outRestTemplate` 注入拦截器
- 拦截所有 HTTP 方法（GET/POST/PUT/DELETE/HEAD/OPTIONS/TRACE/PATCH）
- 支持自动过滤本地/内网地址，避免拦截内部服务调用

**代理 URL 格式**: `{proxy-base}?__url__={url_encoded_original_url}`

**排除规则（自动）**:
1. **本地/内网地址**：自动过滤 127.0.0.1、localhost、192.168.*、10.*、172.16-31.*
2. **IOT物联网平台**：从 `MappingCache.getValue("IOT", "IOT_URL")` 动态读取，支持运行时修改
3. **OSS文件存储**：从 `MappingCache.getValue("OSS", "endpoint")` 动态读取，支持运行时修改
4. **已代理URL**：检测 URL 中已存在的 `__url__=` 参数，避免双重代理

**缓存机制**: IOT 和 OSS 域名采用 60 秒缓存，减少 MappingCache 查询频率。

### 2.4 OutboundProxyBeanPostProcessor — 出站代理 Bean 后处理器

**职责**: 在 Spring 容器初始化完成后，自动向 `outRestTemplate` Bean 注入 `OutboundProxyInterceptor`。

**工作原理**:
- 实现 `BeanPostProcessor` 接口，监听所有 Bean 创建
- 当检测到 `OutRestTemplate` 或名为 `outRestTemplate` 的 `RestTemplate` 时，注入拦截器
- 确保在所有 `outRestTemplate` Bean 定义位置（SpringBoot、OA服务、SCM服务等）都能被拦截

### 2.5 LocalIdUpdater — ID 冲突更新器

**职责**: 上位机检测到社区 ID 冲突（与已注册的其他客户机重复）时，生成新 ID 并 UPDATE 数据库。

**流程**: 解析冲突列表 → `GenerateCodeFactory.getCommunityId()` 生成新 ID → `replaceCommunityId()` 全表 UPDATE → 刷新缓存 → 全量重新注册

### 2.6 SysClientProperties — 配置属性

**前缀**: `sys.client`

详见下文第五节《配置参考》。

## 三、WebSocket 消息协议

### 3.1 消息格式（WsMessage）

```json
{
  "msgId": "uuid",
  "type": "REGISTER",
  "payload": { ... }
}
```

### 3.2 消息类型一览

| 方向 | 类型 | 方向 | 触发时机 |
|------|------|------|----------|
| 上行 | `REGISTER` | 客户机→上位机 | 连接建立后，上报KEY与本地数据 |
| 下行 | `REGISTER_ACK` | 上位机→客户机 | 注册处理结果（OK/CONFLICT/INVALID_KEY） |
| 上行 | `HEARTBEAT` | 客户机→上位机 | 每隔 heartbeat-interval 秒 |
| 下行 | `ACK` | 上位机→客户机 | 心跳应答 |
| 下行 | `INBOUND_REQUEST` | 上位机→客户机 | 上位机转发业务请求 |
| 上行 | `INBOUND_RESPONSE` | 客户机→上位机 | 入站请求处理结果 |

### 3.3 注册消息体（REGISTER payload）

```json
{
  "key": "上位机分配的authKey",
  "localCommunities": [
    { "localCommunityId": "xxx", "communityName": "小区A", "localStoreId": "yyy" }
  ],
  "localStores": [
    { "localStoreId": "yyy", "storeName": "商户A" }
  ],
  "wechatAppIds": [ "wx1234567890" ]
}
```

### 3.4 注册应答（REGISTER_ACK）

| 状态 | 含义 | 处理 |
|------|------|------|
| `OK` | 注册成功 | 启动心跳，进入正常通信 |
| `CONFLICT` | 社区 ID 冲突 | 断开连接 → LocalIdUpdater 解决冲突 → 重连重试 |
| `INVALID_KEY` | KEY 无效 | 断开连接，不再重连 |

### 3.5 入站请求（INBOUND_REQUEST payload）

```json
{
  "method": "GET",
  "path": "/api/user.listUser",
  "headers": { "app-id": "...", "X-Host-Key": "..." },
  "body": "{\"page\":1,\"row\":10}"
}
```

## 四、出站代理业务覆盖范围

### 4.1 拦截范围（自动）

所有通过 `outRestTemplate` 发起的外部 HTTP 请求：

| 业务场景 | 拦截方式 | 说明 |
|---------|---------|------|
| 微信API调用 | ✅ 拦截 | access_token、openid、用户信息等 |
| 微信支付API | ✅ 拦截 | 统一下单、查询订单、退款等 |
| 银联商务API | ✅ 拦截 | access_token、支付、退款等 |
| 第三方支付API | ✅ 拦截 | 畅快支付、瑞支付、宝付等 |
| 短信发送API | ✅ 拦截 | 联麓信息等短信平台 |
| 供应商接口 | ✅ 拦截 | SCM供应商对接 |

### 4.2 排除范围（自动）

| 业务场景 | 排除机制 | 说明 |
|---------|---------|------|
| IOT物联网 | 动态配置 | 从 `MappingCache("IOT", "IOT_URL")` 读取，支持运行时修改 |
| OSS文件上传 | 动态配置 | 从 `MappingCache("OSS", "endpoint")` 读取，支持运行时修改 |
| FTP文件上传 | SDK直连 | 使用 Apache Commons FTPClient/JSch，不经过 outRestTemplate |
| 本地/内网调用 | 自动过滤 | 127.0.0.1、localhost、192.168.*、10.*、172.16-31.* |

### 4.3 配置排除（可选）

通过 `proxy-whitelist-hosts` 和 `proxy-blacklist-hosts` 精确控制代理范围。

## 六、配置参考

### application.yml

```yaml
sys:
  client:
    # 功能开关（默认关闭，关闭时所有客户机代码零影响）
    enabled: true

    # 上位机 WebSocket 地址（必填）
    server-url: ws://your-host:8080/ws/host

    # 上位机分配的认证 KEY（必填）
    auth-key: your-auth-key-here

    # 心跳发送间隔（秒，默认30）
    heartbeat-interval: 30

    # 断线重连最大间隔（秒，默认60）
    reconnect-max-interval: 60

    # 上位机未上线重试间隔（秒，默认600/10分钟）
    host-retry-interval: 600

    # ======== 出站代理配置 ========

    # 上位机 HTTP 代理地址（用于出站代理）
    proxy-url: http://your-host:8080/proxy/out

    # 是否启用出站代理（独立开关，默认启用）
    proxy-enabled: true

    # 代理白名单主机列表（逗号分隔），为空则不限制。白名单模式下仅白名单内的主机走代理
    proxy-whitelist-hosts: api.weixin.qq.com,api-mop.chinaums.com

    # 代理黑名单主机列表（逗号分隔），为空则不限制。黑名单模式下跳过黑名单内的主机
    proxy-blacklist-hosts: localhost,127.0.0.1

    # 代理请求超时时间（秒，默认30秒）
    proxy-timeout: 30
```

### 环境变量（替代方式）

| 变量 | 对应配置 | 默认值 |
|------|----------|--------|
| `SYS_CLIENT_ENABLED` | `sys.client.enabled` | `false` |
| `SYS_CLIENT_SERVER_URL` | `sys.client.server-url` | — |
| `SYS_CLIENT_AUTH_KEY` | `sys.client.auth-key` | — |
| `SYS_CLIENT_PROXY_URL` | `sys.client.proxy-url` | — |
| `SYS_CLIENT_PROXY_ENABLED` | `sys.client.proxy-enabled` | `true` |

## 七、启动与运行

### 7.1 前置条件

1. 上位机已部署并运行，WebSocket 服务端可达
2. 已在上位机管理界面生成客户机注册 KEY（配置页面 → 新客户机注册）
3. 确保客户机网络可访问上位机地址
4. 确保上位机代理服务（`proxy-url`）已部署并运行

### 7.2 启动后流程

```
1. 应用启动 → ApplicationReadyEvent 触发
2. 检测 enabled && isValid → 否则跳过
3. connectToServer(ws://host:port/ws/host)
4. onOpen() → sendRegister() 发送 REGISTER
5. 收到 REGISTER_ACK(OK) → startHeartbeat() 开始心跳
6. OutboundProxyBeanPostProcessor 注入拦截器到 outRestTemplate
7. 进入正常通信: 心跳 / 入站代理 / 出站代理
```

### 7.3 关闭流程

```java
@PreDestroy
onDestroy() {
    stopHeartbeat();       // 停止心跳
    scheduler.shutdown();  // 关闭调度器
    closeQuietly();        // 关闭 WebSocket
}
```

## 八、常见问题

### Q1: 客户机启动时未连接上位机

检查 `sys.client.enabled=true` 和 `server-url`/`auth-key` 配置是否正确。首次连接时若上位机未上线，每10分钟自动重试。

### Q2: 收到 INVALID_KEY 应答

说明 KEY 无效或已吊销。请在上位机配置页面重新生成 KEY，更新配置后重启客户机。

### Q3: 收到 CONFLICT 应答

社区 ID 与已注册的其他客户机冲突。系统会自动调用 `LocalIdUpdater` 生成新 ID 并 UPDATE 数据库，无需人工介入。

### Q4: 上位机拉取数据为空

确认客户机注册成功（上位机在线列表可见）。数据通过 INBOUND_REQUEST 由上位机主动拉取，客户机无需额外配置。

### Q5: 出站代理不生效

检查配置：
1. `sys.client.enabled=true` 和 `proxy-enabled=true`
2. `proxy-url` 配置正确且上位机代理服务可达
3. 确认目标 URL 不是本地/内网地址或已被排除

### Q6: IOT/OSS 域名配置后不生效

IOT 和 OSS 域名缓存时间为 60 秒，修改配置后最多等待 60 秒生效。如需立即生效，可重启客户机。

### Q7: 双重代理问题

拦截器会自动检测 URL 中已存在的 `__url__=` 参数，避免重复转发。
