# MicroCommunity v1.9.1 → v1.9.2 升级文档

| 项目 | v1.9.1 基准 | v1.9.2 目标 | 变更规模 |
|------|------------|------------|---------|
| MicroCommunity（后端） | origin/V1.9.1 (5e35a137) | master (78d51e57) | 96 文件, +6316/-429 |

## 一、新增模块

### 1.1 sys-client — 上位机客户机通信模块（全新）

**路径**: `MicroCommunity/sys-client/`

实现客户机与上位机的分布式通信架构，核心特性：

| 功能 | 实现类 | 说明 |
|------|--------|------|
| WebSocket 长连接 | `SysWebSocketClient.java` (568行) | 连接上位机、注册、心跳、两段式重连 |
| 入站代理 | `InboundProxyHandler.java` (322行) | 验证 Host-Key 后注入管理员身份，绕过权限调用本地 API |
| 出站代理 | `OutboundProxyInterceptor.java` (295行) | 拦截 RestTemplate 外部请求，通过代理转发（支持黑白名单） |
| 统计数据拉取 | `CommunityStatsHandler.java` / `DirectSqlStatsHandler.java` | 处理 DATA_PULL_REQ，直连 SQL 统计房屋/工单/投诉/费用/摄像头数据 |
| ID 冲突处理 | `LocalIdUpdater.java` | 收到 CONFLICT 后批量替换社区 ID（37张关联表）并刷新缓存 |
| 消息模型 | `MessageType.java` / `WsMessage.java` | 统一消息结构体，10种消息类型 |
| 状态缓存 | `StateCache.java` | 从 t_dict 加载状态字典 |
| 启动时序 | `CacheFlushCompleteEvent` 事件机制 | 缓存加载完成后才连接上位机 |

**Maven 依赖**: `spring-boot-starter-websocket`, `java110-core/bean/interface/utils/db`

## 二、后端功能变更

### 2.1 员工微信认证（service-user）

**文件**: `StaffApi.java`

新增 `GET /staff/generatorQrCode` 接口，支持两种模式：

| 模式 | 参数 | URL 结构 | 适用场景 |
|------|------|---------|---------|
| 指定员工 | `staffId` (可选) + 默认 `common=false` | `/app/staffAuth?storeId=xxx&staffId=xxx` | 管理员为特定员工生成认证二维码 |
| 通用认证 | `common=true` | `/app/staffAuth?communityId=xxx`（不带 staffId） | 通用二维码，扫码后跳转员工端登录页自动绑定 |

**文件**: `PcUserLoginCmd.java`（新增 70 行）

新增 `bindStaffAppAuth()` 方法：通用认证二维码扫码登录后，自动将 openId 写入 `staff_app_auth` 表。存在则更新，不存在则新增。

### 2.2 微信关注用户同步重构（service-job）

**文件**: `SynchronizeWechatSubscribeAdapt.java`（173行变更，完全重写）

| v1.9.1 旧逻辑 | v1.9.2 新逻辑 |
|-------------|-------------|
| 全量覆盖同步 | **增量合并**同步 |
| 每次翻页调用 user/get | 先分页拉取 OpenID，再每批 100 调用 batchget |
| 不存储 remark/tagidList | 存储 `remark` 和 `tagidList` 字段 |
| 重复 API 调用 | 每批只调用一次 batchget |

### 2.3 微信关注用户查询（service-user）

**文件**: `ListWechatSubscribeCmd.java`（153行变更）

查询结果新增字段：
- `userId` / `phone` / `name`: 关联 u_user 表获取系统用户信息
- `identityType`: 身份类型（`业主` / `员工` / `业主,员工` / `未绑定`），通过 openId 反向查询 `owner_app_user` 和 `staff_app_auth`

**文件**: `UpdateWechatSubscribeCmd.java`（新增 64 行）

支持修改微信关注用户的 userId 绑定关系。

### 2.4 微信模板缓存优化

**文件**: `WechatTemplateImpl.java`

- `getAllPrivateTemplate()`: 新增 `CommonCache.setValue()` 缓存模板列表
- `getTemplateId()`: 先查缓存，缓存为空再调微信 API，减少重复调用

### 2.5 登录增强

**文件**: `PropertyAppLoginSMOImpl.java`

- 新增密码 MD5 加密处理
- 登录信息增加 `storeTypeCd` 商户类型字段

**文件**: `UserServiceLoginCmd.java`

### 2.6 Logback 日志配置优化（springboot）

## 四、Bug 修复

### 4.1 巡检任务生成

**问题**: 巡检任务明细生成时 `sendFlag` 未初始化

**修复**: `GeneratorInspectionTaskTemplate.java` 第 168 行新增 `inspectionTaskDetailPo.setSendFlag("N")`

**影响模块**: service-job

### 4.2 巡检任务 Mapper 多社区ID

**问题**: 社区 ID 列表参数处理不当，优先覆盖逻辑错误

**修复**: `InspectionTaskServiceDaoImplMapper.xml` - `communityIds` 参数优先于 `communityId`

**影响模块**: java110-db

### 4.3 管理员巡检查询

**问题**: 管理员查询巡检任务时，后端覆盖了前端传入的当前社区 ID 为全部权限社区

**修复**: 使用前端传入的 `communityId`，不再覆盖

**影响模块**: service-community

### 4.4 微信同步重复请求

**问题**: `SynchronizeWechatSubscribeAdapt` 每次翻页对同一批 OpenID 调用两次 `user/get`

**修复**: 先一次性分页拉取所有 OpenID，再按 100 一批调用 `batchget`

**影响模块**: service-job

### 4.5 微信不再返回 nickname/headimgurl

**问题**: 微信 API 不再返回 `nickname` 和 `headimgurl` 字段

**修复**: 改用系统用户表 `u_user` 中的姓名和头像

**影响模块**: service-job, service-user

### 4.6 员工排班任务推送遗漏

**问题**: `NoticeStaffTaskTemplate` 中任务开始时间未到时使用 `return` 中断后续任务

**修复**: 将 `return` 改为 `continue`，跳过当前任务继续处理后续

**影响模块**: service-job

### 4.7 业主身份判断无效数据

**问题**: `owner_app_user` 表中 `user_id` 不在 `u_user` 表中的记录仍被标记为业主

**修复**: 查询时过滤 `user_id` 无效的业主记录

**影响模块**: service-user

### 4.8 Quartz 序列化兼容性

**问题**: Serializable DTO 类缺少显式 `serialVersionUID`，导致 Quartz 反序列化失败

**修复**: `PageDto` 和 `Dto` 类显式定义 `serialVersionUID`

**影响模块**: java110-bean

### 4.9 收据打印模板编译错误

**问题**: `FeePrintPageTemplate` 模块缺少 `communityId` 字段、`PageDto.buildTotalRow` 方法等依赖

**修复**: 补齐缺失依赖

**影响模块**: service-fee

### 4.10 日志配置兼容性

**问题**: Logback 1.2.9 不支持 `createParentDirs` 属性

**修复**: 使用 `${LOG_PATH:-./logs}` 原生语法，通过 `static` 代码块提前创建日志目录

**影响模块**: springboot（所有模块 logback.xml）

## 六、部署升级步骤

### 6.1 后端升级

```bash
# 1. 拉取 v1.9.2 代码
cd MicroCommunity
git checkout v1.9.2

# 2. 执行数据库升级 SQL
# 按顺序执行 docs/db/ 目录下的 SQL 文件：
#   - fee_print_page_template_service_config.sql
```

## 八、注意事项

1. **版本号**: 所有子模块 POM 版本号已统一为 `1.9.2`，不可覆盖父 POM 版本
2. **日志路径**: 使用 Logback 原生语法 `${LOG_PATH:-./logs}`，不再使用 `springProperty`
3. **sys-client 启动时序**: 在 `CacheFlushCompleteEvent` 事件后连接上位机，确保业务数据就绪
4. **IOT 开关**: 未部署 IOT 系统时需在 `t_dict` 表中将 `IOT_SWITCH` 设为非 `ON` 值
5. **通用认证二维码**: 依赖员工端 PropertyApp 编译部署，二维码页面路由为 `/app/staffAuth`
6. **巡检任务**: 任务生成依赖 Quartz 调度器注册，需通过前端「任务管理」页面启动定时任务
7. **wx 关注同步**: 同步操作会调用微信 API，注意调用频率限制（每天有限额）
8. **收据打印模板**: 模板数据以 Base64 编码 HTML 形式存储，反序列化时需正确解码
