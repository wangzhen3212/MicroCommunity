# 自定义收据模板 - 数据库升级执行脚本

## 📋 概述

本文档说明如何将自定义收据模板功能所需的数据库变更应用到正式数据库（TT.sql）。

**升级内容**：
1. 修改 `fee_print_page_template` 表的 `url` 字段类型
2. 在 `c_service` 表中添加3个新服务配置
3. 在 `c_route` 表中添加3条路由权限配置

**适用版本**：MicroCommunity_Copy  
**执行时间**：约5分钟  
**影响范围**：仅新增数据，不影响现有业务

---

## 📝 升级步骤

### 步骤1：修改 fee_print_page_template 表结构

**位置**：TT.sql 第19648-19655行

**原表结构**：
```sql
DROP TABLE IF EXISTS `fee_print_page_template`;
CREATE TABLE `fee_print_page_template` (
  `template_id` varchar(30) NOT NULL COMMENT '页面ID',
  `name` varchar(128) NOT NULL COMMENT '名称',
  `url` varchar(512) NOT NULL COMMENT '收据页面',
  `create_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `status_cd` varchar(2) NOT NULL DEFAULT '0' COMMENT '数据状态 1表示 失效 0 有效'
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

**修改为**：
```sql
DROP TABLE IF EXISTS `fee_print_page_template`;
CREATE TABLE `fee_print_page_template` (
  `template_id` varchar(30) NOT NULL COMMENT '页面ID',
  `name` varchar(128) NOT NULL COMMENT '名称',
  `url` MEDIUMTEXT NOT NULL COMMENT '收据页面URL或压缩后的HTML内容',
  `create_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `status_cd` varchar(2) NOT NULL DEFAULT '0' COMMENT '数据状态 1表示 失效 0 有效'
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

**变更说明**：
- `url` 字段类型从 `varchar(512)` 改为 `MEDIUMTEXT`
- 注释从"收据页面"改为"收据页面URL或压缩后的HTML内容"
- MEDIUMTEXT最大支持16MB，足够存储压缩后的HTML模板

## 🚀 部署后操作

### 1. 重启后端服务

```bash
cd /path/to/springboot/target
nohup java -jar service-api.jar > logs/service-api.log 2>&1 &

# 查看日志
tail -f logs/service-api.log
```

### 2. 清除Redis缓存（可选）

```bash
redis-cli

# 删除服务配置缓存
DEL service_config_cache

# 删除路由缓存
KEYS "*8000418004*"
# 手动删除相关key
```

### 3. 测试功能

1. 访问前端设计器：`http://your-domain/#/views/system/templateColumnDesigner`
2. 配置模板并点击"保存模板"
3. 检查浏览器控制台，应显示：`{"code": 0, "msg": "success"}`

### 问题1：ID冲突


**解决方法**：
```sql
-- 查询当前最大ID
SELECT MAX(id) FROM c_service;
SELECT MAX(id) FROM c_route;

-- 调整INSERT语句中的ID值，确保大于当前最大值
```

### 问题2：service_id冲突

**错误信息**：
```
Duplicate entry '982026061433170163' for key 'service_id'
```

**解决方法**：
```sql
-- 检查service_id是否已存在
SELECT * FROM c_service WHERE service_id = '982026061433170163';

-- 如果存在，生成新的service_id（保持格式一致）
-- 格式：98 + YYYYMMDDHHmmss + 6位随机数
```

### 问题3：仍然报"鉴权失败"

**原因**：Redis缓存未更新

**解决方法**：
```bash
# 1. 确认后端服务已重启
ps aux | grep service-api

# 2. 清除Redis缓存
redis-cli
DEL service_config_cache

# 3. 重新测试
```
