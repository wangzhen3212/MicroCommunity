# 服务管理页面数据显示问题排查

## 📋 问题描述

dev用户登录前端界面 `/pages/dev/serviceManage` 后：
- ❌ **看不到**自定义的接口服务信息（feePrintPageTemplate相关服务）
- ✅ **可以看到**修改、更新操作

## 🔍 问题分析

### 2. Redis缓存检查

后端服务启动时会从数据库加载所有路由配置到Redis缓存。如果缓存未更新，前端将无法看到新添加的服务。

```bash
# 连接Redis
redis-cli

# 检查是否有路由缓存
GET "8000418004_SUFFIX_APP_ROUTE"

# 如果返回nil，说明缓存未加载
# 如果返回数据，检查是否包含新的service_id（982026061566580007等）
```

### 3. 前端API调用检查

服务管理页面调用的API：
- 查询列表：`/service.listServices`
- 保存服务：`/service.saveService`
- 更新服务：`/service.updateService`
- 删除服务：`/service.deleteService`

**注意**：这些是通用的服务管理API，不是feePrintPageTemplate专用的API。

## ✅ 解决方案

### 方案一：重启后端服务（推荐）

这是最简单有效的方法，让系统重新从数据库加载所有配置到Redis。

```bash
# 1. 停止后端服务
kill -9 $(ps aux | grep service-api | grep -v grep | awk '{print $2}')

# 2. 启动后端服务
cd /path/to/springboot/target
nohup java -jar service-api.jar > logs/service-api.log 2>&1 &

# 3. 查看日志确认启动成功
tail -f logs/service-api.log

# 4. 等待30秒后刷新前端页面
```

### 方案二：手动清除Redis缓存

如果不想重启服务，可以手动清除缓存，让系统重新加载。

```bash
# 1. 连接Redis
redis-cli

# 2. 删除服务配置缓存
DEL service_config_cache

# 3. 删除路由缓存
KEYS "*8000418004*"
# 逐个删除返回的key
DEL 8000418004_SUFFIX_APP_ROUTE

# 4. 刷新前端页面，系统会自动重新加载缓存
```

### 方案三：检查数据库配置是否正确

如果上述方法无效，可能是数据库配置有问题。

```sql
-- 1. 检查服务是否存在且状态为在用
SELECT * FROM c_service 
WHERE service_code LIKE 'feePrintPageTemplate.%'
  AND status_cd = '0';

-- 2. 检查路由是否存在且状态为在用
SELECT r.*, s.service_code 
FROM c_route r
LEFT JOIN c_service s ON r.service_id = s.service_id
WHERE r.app_id = '8000418004' 
  AND s.service_code LIKE 'feePrintPageTemplate.%'
  AND r.status_cd = '0'
  AND s.status_cd = '0';

-- 3. 如果发现问题，修正配置
-- 例如：将status_cd改为'0'
UPDATE c_service SET status_cd = '0' WHERE service_code = 'feePrintPageTemplate.saveFeePrintPageTemplate';
UPDATE c_route SET status_cd = '0' WHERE service_id = '982026061566580007' AND app_id = '8000418004';
```

## 📊 常见问题

### Q1: 为什么"修改更新可以看到"？

**原因**：
- 修改、更新操作使用的是已有的通用服务（`service.updateService`、`service.deleteService`）
- 这些服务在数据库中早已存在，且Redis缓存中已有配置
- 而新增的feePrintPageTemplate服务是最近才添加的，缓存可能未更新

**解决**：重启后端服务或清除Redis缓存

### Q2: 如何确认appId是否正确？

**检查前端配置**：
```javascript
// 文件：src/conf/config.js
export default {
    appId: '8000418004',  // ← 这个值
}
```

**检查数据库**：
```sql
SELECT app_id, name FROM c_app WHERE app_id = '8000418004';
-- 预期返回：小区管理系统web端
```

### Q3: 如果仍然看不到怎么办？

**逐步排查**：

1. **检查后端日志**
   ```bash
   tail -f logs/service-api.log | grep -i "feePrintPageTemplate"
   ```

2. **检查浏览器控制台**
   - F12 → Console标签
   - 查看是否有错误信息
   - 查看Network标签中的请求响应

3. **检查数据库连接**
   ```sql
   -- 确认连接的数据库是否正确
   SELECT DATABASE();
   
   -- 确认表是否存在
   SHOW TABLES LIKE 'c_service';
   SHOW TABLES LIKE 'c_route';
   ```

4. **尝试直接调用API**
   ```bash
   # 使用curl测试
   curl -X GET "http://your-domain/api/service.listServices?page=1&row=10&serviceCode=feePrintPageTemplate" \
     -H "appId: 8000418004" \
     -H "userId: dev_user"
   ```

## 🎯 总结

**问题根源**：Redis缓存未更新，导致前端无法看到新添加的服务配置。

**解决方法**：
1. ✅ **首选**：重启后端服务（最彻底）
2. ✅ **备选**：手动清除Redis缓存（快速）
3. ✅ **检查**：验证数据库配置是否正确

**预防措施**：
- 每次修改c_service或c_route表后，务必重启后端服务
- 或者提供后台管理界面的"刷新缓存"功能
- 建立部署 checklist，确保不会遗漏缓存刷新步骤
